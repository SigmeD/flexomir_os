## Как поставляем изменения

Один функциональный инкремент — одна ветка и один PR с кодом, подходящими проверками и относящимися к задаче документами. По умолчанию используем основную папку и обычную ветку; worktree — по согласованию.

Перед merge проверяются фактический PR head, CI, независимое review и нужная приёмка. После merge сверяются main/origin/main и SHA, удаляется remote head завершённого PR, обновляется существующий Drive CURRENT. Документальные исправления могут идти отдельным PR. Полный процесс — в [AGENTS.md](../AGENTS.md).

Сборка, CI, визуальная приёмка, merge, готовность API и выпуск — отдельные состояния. История завершённых планов находится в Git; результаты, необходимые для приёмки, сохранены в профильных отчётах.
