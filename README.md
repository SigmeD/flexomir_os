# Flexomir OS

Ветка COMM-DOCS: общая локальная переписка заказа/поддержки, демонстрационные производственные поля и подписные документы с настоящим PDF-просмотром. [Результат, ручной чек-лист и открытые решения](docs/COMM_DOCS_2026-11-12.md). До Owner-review/merge это отдельная поставка, не состояние main. Owner уточнил: короткое нажатие меняет микрофон/видео, удержание записывает, отпускание готовит запись к отдельной отправке. В бланках есть добавление из заголовка и удаление в просмотре; большой загрузчик показывается только без файлов. «Сохранить» в тикете возвращает к списку поддержки, сохраняя локальную переписку. Локальные ответы в существующий SupportTicket доступны только с `commDemo=1`; серверных прав это не создаёт. Стенд callbacks остаётся по `?view=neutral-actions&mediaPilot=1`.

Flexomir OS — личный кабинет для клиентов типографии и рабочее место её менеджеров. Клиент оформляет заказ, добавляет продукцию и макеты, следит за выполнением и обращается в поддержку. Менеджер просматривает поступившие заказы, работает с компаниями и при необходимости обращается в поддержку.

## Что можно попробовать сейчас

В этом репозитории находится интерфейс приложения на React и TypeScript. Он работает с демонстрационными данными: можно пройти путь от создания заказа у клиента до его просмотра у менеджера.

В кабинете клиента доступны:

- Список заказов с фильтрами и подробной информацией о каждом заказе.
- Создание заказа, добавление и редактирование позиций, повтор завершённого заказа.
- Желаемый и согласованный сроки: согласованная дата видна только для чтения, в новом заказе поле пустое.
- Выбор файла с компьютера и работа с разделом «Мои макеты».
- Создание и просмотр обращений в поддержку.
- Настройки профиля.

В кабинете менеджера доступны списки новых и всех заказов, просмотр заказа и его позиций, создание черновика для выбранной компании, список компаний и обращения в поддержку.

Интерфейс рассчитан на компьютер, планшет и телефон. Оба кабинета используют общие элементы: навигацию, формы, карточки, кнопки и меню.

## Запуск и проверки

Для запуска нужны Node.js и npm. В разработке используется Node.js 24, в автоматических проверках — Node.js 22.

Из папки проекта:

```powershell
npm ci
npm run dev
```

Приложение откроется по адресу [http://127.0.0.1:5173](http://127.0.0.1:5173/). Если порт занят, используйте адрес, который появится в терминале.

- [Кабинет клиента](http://127.0.0.1:5173/?view=client-orders).
- [Кабинет менеджера](http://127.0.0.1:5173/?view=manager-orders).
- [Демонстрация со сменой роли](http://127.0.0.1:5173/?view=client-orders&demoTools=1).

Чтобы проверить один заказ с обеих сторон, откройте демонстрацию со сменой роли. Создайте и отправьте заказ от клиента, затем через кнопку «Демо» переключитесь на менеджера в той же вкладке. Новая вкладка начинает отдельную демонстрацию.

Проверка TypeScript и сборка приложения:

```powershell
npm run build
```

Браузерные тесты:

```powershell
npx playwright install chromium firefox webkit
npm run test:e2e -- --workers=2
```

Матрица новой переписки/PDF и синтетического media lifecycle в Chromium/Firefox/WebKit/touch:

```powershell
npx playwright test --config=playwright.comm-docs.config.ts --workers=2
```

Native recording tests отдельно пропускаются в движках без MediaRecorder с указанной причиной; unsupported fallback проверяется. Физические устройства и настоящий iPhone этим не проверяются. Доказательства сохраняются в `output/comm-docs/` и CI artifact `comm-docs-evidence`.

Дополнительные проверки компонентов и визуальных эффектов описаны в [критериях проверки](docs/QA_CHECKLIST.md), [отчёте по материалу Glass](docs/fos-glass-material.md) и [проверке Select](docs/glass-select-check.md). Снимки и видео тестовых прогонов сохраняются локально и не входят в репозиторий.
